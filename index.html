Session 3: Transport Layer Masterclass

المرجع الهندسي المتخصص لطبقة النقل (Layer 4)، بروتوكولات TCP و UDP، الهيدر، المآخذ (Sockets)، والبورتات.

🚀 1. ما بعد عنوان الـ IP (Beyond the IP Address)
🎯 القاعدة الذهبية لطبقة النقل

"IP finds the host. Layer 4 finds the application."

عنوان الـ IP يوصلك لحد العمارة (الجهاز)، لكن طبقة النقل والبورتات بتوصلك لرقم الشقة (التطبيق المحدد جوه الجهاز)[cite: 23].

المهام الأساسية لطبقة النقل (Layer 4):

• Segmentation (التقطيع): تقطيع البيانات الكبيرة إلى أجزاء صغيرة يسهل تتبعها وإرسالها[cite: 23].

• Flow Control (التحكم في التدفق): تنظيم حركة البيانات لمنع حدوث ضغط أو انهيار في استقبال البيانات[cite: 23].

• Multiplexing (الإرسال المتعدد): استخدام البورتات لتشغيل أكثر من تطبيق واستقبال البيانات في نفس الوقت[cite: 23].

• Error Handling (معالجة الأخطاء): اكتشاف الباكت الضائعة أو التالفة وبدء استعادتها[cite: 23].

📦 2. تحليل عبء الترويسات (Header Overhead Breakdown)
مقارنة ترويسات TCP و UDP
بروتوكول TCP (حجم متغير من 20 إلى 60 بايت)

• منافذ المصدر والوجهة (Source & Destination Ports) بحجم 16 بت لكل منهما[cite: 24].

• أرقام التسلسل والتأكيد (Sequence & Acknowledgment Numbers) بحجم 32 بت لكل منهما[cite: 24].

• علامات التحكم (Control Flags): مثل SYN, ACK, FIN, RST, PSH, URG[cite: 24].

• التحكم في التدفق عبر نافذة ديناميكية (Dynamic Window Size) بحجم 16 بت[cite: 24].

• يضمن تسليم البيانات بنجاح (Guaranteed delivery) ولكن على حساب زيادة عبء المعالجة[cite: 24].

بروتوكول UDP (حجم ثابت 8 بايت فقط)

• منفذ المصدر (Source Port) بحجم 16 بت[cite: 24].

• منفذ الوجهة (Destination Port) بحجم 16 بت[cite: 24].

• طول البيانات (Datagram Length) بحجم 16 بت[cite: 24].

• فحص الأخطاء (Checksum) بحجم 16 بت[cite: 24].

• بصمة خفيفة جداً (Minimal footprint) لتحقيق أقصى سرعة في التدفق (Ultra-fast throughput)[cite: 24].

🔄 3. دورة حياة اتصال TCP (Handshake & Teardown)
المصافحة الثلاثية والإنهاء الآمن
أولاً: إنشاء الاتصال (Establishment - 3-Way Handshake)[cite: 25]

• Step 1 [SYN]: العميل يبدأ الاتصال ويرسل رقم التسلسل الأولي (Initial Sequence Number - ISN)[cite: 25].

• Step 2 [SYN + ACK]: الخادم يرد مؤكداً الاستلام ومزامناً للبيانات[cite: 25].

• Step 3 [ACK]: العميل يرسل التأكيد النهائي وتنتقل الجلسة لحالة ESTABLISHED[cite: 25].

ثانياً: الإغلاق النظيف (Graceful Teardown)[cite: 25]

• Step 1 [FIN]: أحد الطرفين يرسل طلب إنهاء الاتصال (Active close)[cite: 25].

• Step 2 [ACK]: الطرف الآخر يؤكد استلام الإغلاق[cite: 25].

• Step 3 [FIN + ACK]: المصافحة النهائية لتحرير مآخذ التوصيل (Sockets) ونظافة الذاكرة[cite: 25].

🔌 4. الـ Sockets، تصنيفات البورتات، والـ Multiplexing
ما هو الـ Network Socket؟ (مع مثال واقعي)

هو اتحاد عنوان الـ IP الخاص بالجهاز مع رقم البورت في طبقة النقل[cite: 26].

المعادلة: Network Socket = Host IP Address + Layer 4 Port Number[cite: 26]

مثال واقعي: عندما يتصل جهازك 192.168.1.10 عبر البورت المؤقت 49153 بسيرفر الويب 192.168.1.100 عبر البورت 80، فإن الاتصال يمثل السوكت التالي: 192.168.1.10:49153 talking to 192.168.1.100:80[cite: 26].

تصنيفات البورتات (Port Classifications)

1. Well-Known Ports (0 - 1023): محجوزة للخدمات القياسية العالمية بواسطة IANA[cite: 26]:

  • Port 80 / 443: للويب (HTTP / HTTPS)[cite: 26, 27].
  • Port 53: لنظام أسماء النطاقات (DNS)[cite: 26, 27].
  • Port 20 / 21: لنقل الملفات (FTP).
  • Port 22: للاتصال الآمن (SSH).
  • Ports 67 / 68: لتوزيع الآبيات (DHCP)[cite: 27].

2. Registered Ports (1024 - 49151): مخصصة لتطبيقات الشركات[cite: 26]:

  • Port 3306: لقواعد بيانات MySQL[cite: 26].
  • Port 3389: للتحكم عن بعد في الويندوز (RDP)[cite: 26].

3. Dynamic / Ephemeral Ports (49152 - 65535): بورتات مؤقتة يمنحها نظام التشغيل عشوائياً للعميل وقت فتح الاتصال[cite: 26].

خاصية الإرسال المتعدد عبر البورتات (Port Multiplexing)

تسمح لجهازك الذي يمتلك عنوان IP واحد أن يشغل متصفح ويب، ويستعلم عن DNS، ويفتح برنامج FTP في نفس اللحظة، حيث يوجه نظام التشغيل البيانات الواردة لكل تطبيق بدقة بناءً على البورت الخاص به[cite: 28].

🏗️ 5. مصفوفة القرار المعمارية (Architectural Decision Matrix)
معضلة المهندس (The Architect's Dilemma):
"A banking app using UDP is a security disaster. A live 4K stream using TCP is a buffering nightmare. Choose your protocol wisely."[cite: 29]

1. Live 4K Video Broadcast: البروتوكول: UDP. الأولوية للتدفق اللحظي وإسقاط الفريمات التالفة أفضل من تأخير الإعادة[cite: 30].

2. Secure Core Banking Database: البروتوكول: TCP. الأولوية المطلقة لسلامة البيانات وعدم السماح بفقدان أي بايت[cite: 30].

3. Competitive Esports FPS Gameplay: البروتوكول: UDP. تحديث الإحداثيات الفوري أهم من الباكتات القديمة[cite: 30].

4. Operating System Firmware Update: البروتوكول: TCP. التحقق التام من الحمولة ضروري، وفقدان بت واحد يدمر التثبيت[cite: 30].
