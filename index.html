Session 3: Transport Layer Masterclass

المرجع الهندسي المتخصص لطبقة النقل (Layer 4)، بروتوكولات TCP و UDP، المآخذ (Sockets)، وتفاصيل البورتات.

🚀 1. ما بعد عنوان الـ IP (Beyond the IP Address)
🎯 القاعدة الذهبية لطبقة النقل

"IP finds the host. Layer 4 finds the application."

عنوان الـ IP يوصلك لحد الجهاز (العمارة)، لكن طبقة النقل والبورتات بتوصلك للتطبيق المحدد جوه الجهاز (رقم الشقة).

المهام الأساسية لطبقة النقل (Layer 4):

• Segmentation (التقطيع): تقطيع البيانات الكبيرة إلى أجزاء صغيرة يسهل تتبعها وإرسالها.

• Flow Control (التحكم في التدفق): تنظيم حركة البيانات لمنع حدوث ضغط أو انهيار في استقبال البيانات.

• Multiplexing (الإرسال المتعدد): استخدام البورتات لتشغيل أكثر من تطبيق واستقبال البيانات في نفس الوقت.

• Error Handling (معالجة الأخطاء): اكتشاف الباكت الضائعة أو التالفة وبدء استعادتها.

📦 2. تحليل عبء الترويسات (Header Overhead Breakdown)
مقارنة ترويسات TCP و UDP
بروتوكول TCP (حجم متغير من 20 إلى 60 بايت)

• منافذ المصدر والوجهة بحجم 16 بت لكل منهما.

• أرقام التسلسل والتأكيد بحجم 32 بت لكل منهما.

• علامات التحكم (Control Flags): مثل SYN, ACK, FIN, RST, PSH, URG.

• التحكم في التدفق عبر نافذة ديناميكية (Dynamic Window Size) بحجم 16 بت.

• يضمن تسليم البيانات بنجاح (Guaranteed delivery) ولكن على حساب زيادة عبء المعالجة.

بروتوكول UDP (حجم ثابت 8 بايت فقط)

• منفذ المصدر ومنفذ الوجهة بحجم 16 بت لكل منهما.

• طول البيانات (Datagram Length) بحجم 16 بت.

• فحص الأخطاء (Checksum) بحجم 16 بت.

• بصمة خفيفة جداً لتحقيق أقصى سرعة في تدفق البيانات (Ultra-fast throughput).

🔄 3. دورة حياة اتصال TCP (Handshake & Teardown)
المصافحة الثلاثية والإنهاء الآمن
أولاً: إنشاء الاتصال (Establishment - 3-Way Handshake)

• Step 1 [SYN]: العميل يبدأ الاتصال ويرسل رقم التسلسل الأولي (ISN).

• Step 2 [SYN + ACK]: الخادم يرد مؤكداً الاستلام ومزامناً للبيانات.

• Step 3 [ACK]: العميل يرسل التأكيد النهائي وتنتقل الجلسة لحالة ESTABLISHED لبدء نقل البيانات الفعلي.

ثانياً: الإغلاق النظيف (Graceful Teardown)

• Step 1 [FIN]: أحد الطرفين يرسل طلب إنهاء الاتصال.

• Step 2 [ACK]: الطرف الآخر يؤكد استلام طلب الإغلاق.

• Step 3 [FIN + ACK]: المصافحة النهائية لتحرير مآخذ التوصيل (Sockets) ونظافة الذاكرة.

🔌 4. الـ Sockets، تصنيفات البورتات، والـ Multiplexing
ما هو الـ Network Socket؟ (توضيح تفصيلي بمثال)

الـ Socket هو العنوان الكامل للاتصال. لو تخيلنا أن الـ IP هو عنوان العمارة، فإن رقم البورت هو رقم الشقة أو الغرفة. لو بعت بيانات بالـ IP بس، هتوصل العمارة ومحدش هيعرف هي رايحة لأي برنامج! ولو بالبورت بس، مفيش عنوان للجهاز. لازم الاثنين مع بعض.

المعادلة: Network Socket = Host IP Address + Layer 4 Port Number

مثال واقعي: عندما يفتح متصفحك على جهازك 192.168.1.10 بورت مؤقت عشوائي 49153 ليتكلم مع سيرفر جوجل 142.250.190.46 عبر بورت الويب المشفر والمحدد 443، فإن الاتصال بالكامل يمثل السوكت التالي:
192.168.1.10:49153 talking to 142.250.190.46:443

تصنيفات البورتات (Port Classifications) بالتفصيل

1. Well-Known Ports (0 - 1023): عائلة المنافذ المعروفة التي تضم 1024 بورت. هذه الأرقام ليست رينجاً متصلاً يؤدي وظيفة واحدة، بل هي أرقام منفصلة وكل رقم مستقل بذاته وليه تطبيق شكل (وهذه أمثلة مشهورة وليست كل البورتات):

  • Port 80: مخصص حصرياً للويب الغير مشفر (HTTP) - اتصال غير آمن.
  • Port 443: مخصص حصرياً للويب المشفر (HTTPS) - اتصال آمن ومحمي.
  • Port 53: مخصص حصرياً لخدمة ترجمة أسماء النطاقات (DNS).
  • Port 22: مخصص حصرياً للتحكم الآمن في السيرفرات عن بعد (SSH).
  • Port 20 / 21: مخصصان لبرنامج نقل الملفات (FTP).
  • Ports 67 / 68: مخصصان لتوزيع عناوين الآي بي تلقائياً (DHCP).

2. Registered Ports (1024 - 49151): منافذ مسجلة ومخصصة لتطبيقات الشركات:

  • Port 3306: مخصص لقواعد بيانات MySQL.
  • Port 3389: مخصص لخدمة سطح المكتب البعيد (RDP) في الويندوز.

3. Dynamic / Ephemeral Ports (49152 - 65535): بورتات مؤقتة يمنحها نظام التشغيل عشوائياً لبرامج العميل وقت فتح الاتصال.

خاصية الإرسال المتعدد عبر البورتات (Port Multiplexing)

هي الخاصية التي تسمح لجهازك (الذي يمتلك عنوان IP واحد) بفتح متصفح ويب، وتنزيل ملف، وتشغيل لعبة أونلاين في نفس اللحظة؛ حيث يوجه نظام التشغيل البيانات الواردة والصادرة لكل تطبيق بدقة تامة بناءً على رقم البورت الخاص به من غير أي تداخل.

🏗️ 5. مصفوفة القرار المعمارية (Architectural Decision Matrix)
معضلة المهندس (The Architect's Dilemma):
"A banking app using UDP is a security disaster. A live 4K stream using TCP is a buffering nightmare. Choose your protocol wisely."

1. Live 4K Video Broadcast: البروتوكول المستخدم: UDP. الأولوية للتدفق اللحظي، وإسقاط الفريمات التالفة أفضل بكثير من حدوث تاخير (Lag) بسبب طلب الإعادة.

2. Secure Core Banking Database: البروتوكول المستخدم: TCP. الأولوية المطلقة لسلامة البيانات وعدم السماح نهائياً بفقدان أو إعادة ترتيب أي بايت.

3. Competitive Esports FPS Gameplay: البروتوكول المستخدم: UDP. لأن الإحداثيات والحركة الفورية أهم بكثير من البيانات القديمة.

4. Operating System Firmware Update: البروتوكول المستخدم: TCP. التحقق التام من الحمولة ضروري، حيث أن فقدان بت واحد يؤدي لفشل التثبيت كلياً.
